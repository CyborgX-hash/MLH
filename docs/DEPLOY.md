# Deploying DeciTrace on free tiers (Render + Neon + OpenRouter)

| Part | Service | Plan |
|---|---|---|
| API (FastAPI) | Render web service `decitrace-api` | Free |
| Frontend (React) | Render static site `decitrace-web` | Free |
| Database (PostgreSQL + pgvector) | [Neon](https://neon.com) (Supabase also works) | Free |
| Model (Qwen3.6-27B, open weights) | [OpenRouter](https://openrouter.ai) | Pay per use, about a cent per extraction run |

The models run at OpenRouter, so the API needs no GPU and fits Render's free instance (0.1 CPU, 512 MB).

## 1. Database (Neon)

1. Create a Neon project and copy its connection string. It looks like
   `postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`.
2. Nothing else to do: DeciTrace accepts `postgres://` and `postgresql://` URLs as given, and its first migration
   runs `CREATE EXTENSION IF NOT EXISTS vector`, which Neon supports on every plan.

## 2. Keys

- **GitHub token:** a fine-grained token with read-only access to public repositories.
- **OpenRouter key** for the model.
- Create fresh keys for the deployment. Never reuse a key that was pasted into a chat or committed anywhere.

## 3. Render Blueprint

1. Push this repository to GitHub, then in Render choose **New → Blueprint** and select it. Render reads
   [`render.yaml`](../render.yaml) and creates `decitrace-api` and `decitrace-web`.
2. When asked, enter the secrets:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string |
   | `GITHUB_TOKEN` | your GitHub token |
   | `AI_API_KEY` | your OpenRouter key |
   | `CORS_ORIGINS` | `["https://decitrace-web.onrender.com"]` (your static site's URL, as a JSON list) |
   | `VITE_API_BASE_URL` | `https://decitrace-api.onrender.com` (your API's URL, no trailing slash) |

   The model settings (`AI_MODEL=qwen/qwen3.6-27b`, reasoning disabled, full-text retrieval) are already in the
   Blueprint. `DECITRACE_ADMIN_TOKEN` is generated by Render; read it in the API's Environment tab if you need the
   admin endpoints.
3. Render URLs are only known after the first deploy. If yours differ from the names above, update
   `CORS_ORIGINS` (API) and `VITE_API_BASE_URL` (static site) in each service's Environment tab, then redeploy
   both. `VITE_API_BASE_URL` is baked in at build time, so the static site must be rebuilt after changing it.
4. Every API start runs `alembic upgrade head`, so the schema is created on the first deploy and updated on
   later ones.

## 4. Check it

- `https://<api>.onrender.com/api/health` should return `"status": "ok"` with `pgvector: true` and
  `github_token_configured: true`.
- Open the static site, connect a repository, wait for **Processing completed**, press **Extract decisions**,
  then ask a question.

## Alternative: frontend on Vercel

Instead of Render's static site, the frontend can run on Vercel, with the API still on Render.

| Vercel setting | Value |
|---|---|
| Framework preset | Vite |
| Root directory | `frontend` |
| Install command | `npm ci` |
| Build command | `npm run build` |
| Output directory | `dist` |
| Environment variable | `VITE_API_BASE_URL=https://<your-api>.onrender.com` (no trailing slash; redeploy after changing it) |

`frontend/vercel.json` rewrites every path to `index.html`, so direct links such as `/repos/2/decisions` work.
On the Render API, set `CORS_ORIGINS=["https://<your-project>.vercel.app"]`. Vercel preview deployments get
other URLs, which CORS blocks unless you add them to that list.

Use Neon's **direct** connection string (host without `-pooler`) as `DATABASE_URL`. The pooled one goes through
PgBouncer, which can break the server-side prepared statements the psycopg driver uses.

## What to expect on free plans

- **Cold starts:** the free API sleeps after about 15 minutes idle; the first request then takes 30–60 seconds,
  and Neon's free database also scales to zero. Open the site a minute before a demo.
- **Background work runs inside the web process.** If Render stops or restarts the instance during a sync or an
  extraction, the job is marked as interrupted when the API starts again; start it again from the dashboard.
- **Large repositories.** With a token, one sync reads up to about 1,000 issues and 500 pull requests. On a
  0.1-CPU instance the first sync of a big repository can take several minutes.
- **No user accounts.** Anyone who can open the site can start syncs and extractions that spend your GitHub and
  OpenRouter quotas. Share the URL only with judges, and suspend the services after the event. See
  [AUDIT.md](AUDIT.md).

## How this was verified

The Blueprint's exact start and build commands were run locally against a brand-new empty database, given as a
`postgres://` URL with production-style settings:
- all six migrations applied and `/api/health` reported `ok`;
- CORS allowed the configured frontend origin and refused others;
- the static build had the API URL baked in, and client-side routes loaded from deep links;
- connecting `pallets/itsdangerous` synced 125 issues, 493 comments, 312 pull requests and 677 commits with no
  errors (658 GitHub requests);
- **Extract decisions** produced 9 decisions with Qwen3.6-27B via OpenRouter, with none refused;
- Ask DeciTrace answered with citations to the maintainer's real comments on PR #186.

The deployment on Render itself has not been performed by us; do the checks in step 4 after deploying.
